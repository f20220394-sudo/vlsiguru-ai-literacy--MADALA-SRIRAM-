# Mission 3 — Is It Really AI?

## Classification table

| System | Main classification | Reason |
|---|---|---|
| Basic calculator | Traditional software / rule-based | Applies explicit arithmetic operations to the inputs |
| Temperature warning triggered at a fixed threshold | Traditional software / rule-based | A specified condition triggers a warning |
| Spam filter | Often ML-based AI | Many spam filters classify messages using learned patterns; implementations vary |
| Document summarizer | Often generative AI | A modern AI summarizer may generate a shorter version of the source text; implementations vary |
| Traffic ETA prediction | Often ML-based AI plus other software | ETA systems can estimate travel time from historical and live signals; the exact method varies |

## One easy classification

A basic calculator is easy to classify as traditional software because it follows defined arithmetic operations for the supplied input.

## One difficult classification

A spam filter can be difficult to classify without knowing its implementation. It might use hand-written rules, a learned classifier, or a combination of methods. The label alone is not enough evidence.

## My own example

A digital alarm that rings at 6:30 a.m. is usually traditional software: it compares the current time with a stored alarm time and triggers an action. It does not need to learn from data.

## Conclusion

The key question is whether the system mainly follows explicit programmed rules, learns patterns from data, or generates content. Real products may combine several approaches.
